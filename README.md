# iSicnu

一站式四川师范大学服务平台。

- 应用名称：iSicnu
- 包名 / applicationId：`com.gakiji.isicnu`
- 最低系统：Android 12 / minSdk 31
- 目标系统：Android 17 / compileSdk、targetSdk 37

## 开发与构建

使用 Android Studio 打开当前目录，选择 JDK 17 或更高版本，安装 Android SDK Platform 37。
SDK 路径通过 `ANDROID_HOME` 或本机 `local.properties` 的 `sdk.dir` 指定。

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

安装包：`app/build/outputs/apk/debug/iSicnu-0.22.0.apk`。Gradle 自动按 `iSicnu-版本号.apk` 命名，后续打包也沿用此规则。
本机可使用 Android Studio 自带的 JDK：

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' \
ANDROID_HOME="$HOME/Library/Android/sdk" \
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Android 17 的 SDK 37 配置见 [Android 官方说明](https://developer.android.com/about/versions/17/setup-sdk)。

## 当前登录行为

- 浅绿 / 深绿的银杏主题登录页，打开校方统一认证网页完成密码、验证码或 MFA。
- 默认由用户在校方页面输入密码，不保存密码。用户可以在个人中心自愿开启快速登录 Beta（见下文）。认证结束后独立请求本科教务个人资料验证会话。
- 以教务返回的真实学号识别身份：10 位数字进入本科生首页；11 位识别为研究生并提示尚未开放；其他格式不接受为有效学生身份。
- Cookie 和 sid 使用 Android Keystore / AES-GCM 加密保存到应用私有的 noBackup 目录；加密失败仅保留本次内存会话，并显示提示。
- 已认证的本科生资料与会话一并加密保存。冷启动先展示本机资料和缓存，再后台请求校方接口；这是离线浏览状态，不代表服务端 Cookie 仍有效。旧版本没有保存资料时，仅在升级后的首次启动验证一次以完成迁移。
- 退出清除本机加密会话、校园缓存、WebView Cookie、网页存储及 Beta 保存的账号密码；不等同于注销学校所有客户端上的登录。
- 研究生服务尚未接入。

学校旧本科教务入口使用 HTTP；课表 CAS 的历史服务地址也使用 HTTP。网络配置仅对精确 IP `202.115.194.60` 与主机 `jwcxk.sicnu.edu.cn` 放行明文，应用来源策略进一步限制后者只能用于 `/student/sso/login`。其他课表请求和统一认证入口强制 HTTPS，证书验证失败时停止连接。学校 HTTP 链路的固有限制仍然存在。

## 后台同步与缓存

- 登录后及冷启动自动加载缓存并同步课表、成绩、二课；App 回到前台也会刷新，60 秒内的重复前台事件合并。
- 原生 `JobScheduler` 注册唯一的约一小时周期任务，有网络且电量不低时运行，跨重启保留；不常驻前台服务，不申请精确闹钟或电池白名单。系统省电、强制停止和厂商后台策略可能延后任务，周期语义见 [Android 官方文档](https://developer.android.com/reference/android/app/job/JobInfo.Builder#setPeriodic(long))。
- 课表沿用已有 CAS 换票；成绩 sid 失效时尝试现有 CAS 会话换取新 sid，验证学号后重试一次；二课支持可信站点内的 HTTP 跳转换票，并校验当前二课学号。不提交后台密码、不自动触发 MFA；服务端要求交互时由用户点击认证。
- 各系统独立更新；失败保留原缓存与时间，不把失败当空列表，也不自动拉起 Activity 或 WebView。
- 前后台会话及缓存提交共用锁，按账号、sid 和缓存清理代次校验；各系统只合并自己的数据，避免互相覆盖。退出取消周期任务，旧会话/旧账号/清理前的请求不能写回缓存。
- 本机资料、Cookie、sid、校园缓存仍使用现有 Keystore 加密保存；计划任务不包含密码或 Cookie。

## 快速登录 Beta

个人中心 → 快速登录 Beta → 输入当前学号、密码并勾选同意。默认关闭，不预先导入其他项目的 Cookie 或凭据。

- 仅接受与当前已认证本科生学号相同的账号。
- 密码在 `noBackupFilesDir/beta-credentials.enc` 使用现有 Android Keystore / AES-GCM 加密，不写明文、不上传 iSicnu、机器人服务器或统计服务。
- 自动登录需要将凭据直接提交给学校 HTTPS 认证服务；“不上传”指不上传我们的服务器，并非登录时不经过网络。
- 后台优先复用 Cookie 和已有 CAS 会话，不自动打开认证页面。确实需要密码、验证码或 MFA 时保留缓存和认证提示，由用户点击认证；Beta 在该页面自动填写并提交一次，旋转重建不会重新提交。
- 验证码、设备验证和学校页面结构变化时交还手动操作，不自动确认“信任设备”。认证页“刷新”保留当前 WebView、Cookie 与页面地址，不重启认证，也不重复自动提交已消费的凭据。
- 关闭 Beta 删除本机账号密码，已有 Cookie 可继续使用；退出登录也删除账号密码。删除操作与尚未完成的保存操作串行，避免旧任务重新写回。
- 凭据不放入 Compose 的可恢复状态；设置弹窗与认证页阻止系统截图。密码对象的字符串表示不含账号密码。
- 二课认证后验证当前用户并通过新 CAS 票据校验与当前教务账号一致，校验失败时不合并会话。

二课逻辑来自本地 V6 源码，只读取实现方式；没有读取或复制其生产凭据、Cookie、浏览器状态或机器人配置。来源和限制见 [二课与 Beta 开发说明](docs/second-class-beta.md)。

认证页直接使用系统 WebView 默认的手机版浏览行为，已移除电脑版切换、空白检测和自动重载。刷新保留当前页面、Cookie 与多因子 URL；一次性 ticket/sid 回调、内部错误页或空白页使用安全入口/上一次校方页面恢复。真正切换登录轮次时重新绑定 AndroidView，避免显示已销毁的 WebView。

V6 代码确认 `MULTIFACTOR_BROWSER_FINGERPRINT` Cookie 与认证站点 localStorage 的 `browser_fingerprint` 需要一致。App 在已有指纹时，从加密会话中的 Cookie 恢复该值，再打开校方页面；首次使用没有该值时直接进入官方流程。不会自动点击“信任设备”，也不保证学校以后永不要求验证。退出仍清除本机状态。

H5 子资源加载失败、HTTP 错误、脚本错误会在认证页显示精简的“加载信息”。不显示或保存原始控制台内容、URL 参数、Cookie、密码或令牌，不上传诊断。证书和 HTTPS 检查保持不变。

2026-10-28 真机 ADB / WebView 调试确认：多因子页脚本、样式和认证表单已正常加载，但 `innerHeight=753` 时 CSS `100vh=0`，导致 `.mobile-page-center-box` 高度为 0、内容被裁切。临时将内容区域恢复为 `innerHeight - 44` 后，高度变为 709，用户确认验证码表单恢复显示；未提交认证或改动 Cookie。v0.3.3 在原生 WebView 创建时明确设置宽高 `MATCH_PARENT`，避免默认 `WRAP_CONTENT` 的视口高度行为，符合 [Android WebView 尺寸建议](https://developer.android.com/develop/ui/views/layout/webapps/best-practices)。临时网页样式不写入 App，新安装包仍需在该设备验证无需临时修正即可显示。

## 2026-10-28 课表误报核查

真机抓取的仅为 HTTP 状态、固定路径类别和 Cookie 属性，不记录 Cookie 值、密码、账号、票据或 URL 参数。确认两个独立问题：

1. 学校 SSO 下发的部分 Cookie 未标注 Secure，原 CookieJar 直接丢弃，导致有效 CAS 票据落地后再次回到登录。现在保留精确可信主机及已允许的旧 SSO 回调所设 Cookie，并将非旧教务 Cookie 强制存为 HTTPS-only；没有放宽地址白名单或证书检查，也不会在 HTTP 回调请求中发送这些 Cookie。
2. 登录课表系统后，课表入口与当前学期接口均 HTTP 200，该账号可用学期共 4 项，未包含校方返回的当前学期。这是“当前学期未提供课表”，不是当前账号登录失效，也不据此自行推断毕业状态。现在缓存独立的 currentUnavailable 标记，显示“本学期暂无课表”，保留可用学期选择，不用历史学期冒充今日课程。正常返回空课程数组仍按空课表显示；异常结构仍报错；HTTP 403 显示权限不足，不诱导反复登录。

临时调试日志已从交付代码移除。v0.4.1 已通过 ADB 覆盖安装，真机首页确认显示“本学期暂无课表”，不再显示认证或网络错误。35 项单元测试通过，Lint 无错误；覆盖 HTTPS/旧回调 Cookie 保留且仅 HTTPS 发送、真实空课表、当前学期不在可用列表、缓存还原、异常学期结构和 HTTP 403 权限不足。尚未逐项查询历史学期的具体课程，也没有根据学号或该响应自动判定毕业状态。

## 0.10.2 后台自动重连

修复两条独立缺口：旧 Beta 只为前台 WebView 填写表单，后台 CampusSyncStorage.renew 仅用现有 CAS Cookie 换票；原重新认证按钮直接调用 beginAuth。现在会话过期后先以 Cookie 静默换票，失效后按当前账号读取已同意保存的本机加密凭据，通过学校 HTTPS CAS 登录。课表、成绩、二课、四项本科教务及执行计划详情的普通失败恢复都走后台；定时任务复用同一路径，不启动 Activity。

学校公开登录页与 login.js/encrypt.js 在 2026-10-28 匿名读取：表单 pwdFromId，用户名 username、密文 password、execution/_eventId/cllt/dllt 等隐藏字段；passwordText 是前端原密码输入，官方 JS 提交前禁用它。使用 AES/CBC/PKCS5Padding + 64 字符随机前缀与 16 字符随机 IV，与校方加密逻辑一致；不采用官方 JS 失败时回退明文的分支。POST 只允许学校精确 HTTPS CAS 地址，不把密码转发到重定向地址。提交前请求公开脚本指定的 /authserver/checkNeedCaptcha.htl，遇图形/滑块验证码停止。返回 sid/研究生门户后重新校验身份，再保存 Cookie；研究生先初始化教务子应用。

恢复过程串行，同一账号/会话/凭据版本的失败保留 60 秒，阻止多个模块并发重复提交密码。修改 Beta 凭据或主动后台重试可重新尝试；关闭 Beta、切换账号或退出导致授权版本改变时，在提交密码前停止。账号校验、账号缓存隔离与旧请求失效保护继续保留。

“后台重连”只刷新后台数据；不会自动打开浏览页面。验证码、多因子、无可用本机凭据、密码被拒绝或无法识别认证页时，显示具体提示及独立的“完成校方验证”按钮，用户主动点击才进入应用内学校认证页。普通网络错误不要求重新登录；二课空态也不再一律写成“需要认证”。设置保存 Beta 后立即发起数据刷新，遇失效会话时会实际使用本机凭据。

## 0.14.0 系统桌面小组件

全部 10 张首页卡片提供三种尺寸，共 30 个系统小组件入口。可以在首页长按进入编辑，点击加号，在卡片库选择“添加到桌面”；也可以在系统桌面长按空白处，打开小组件列表，选择 iSicnu。主屏上的尺寸由桌面网格决定，拖动缩放时自动切换紧凑、横向和大卡布局。

复用按账号加密的校园缓存，无第二份明文桌面数据文件；切换、退出账号以及清理缓存会刷新桌面。点击进入对应功能，热榜/通知条目交给 QQ。成绩默认隐藏分数，后台同步不会为了桌面卡片自动打开浏览页。首次使用仍需在 App 完成学校登录与同步。机制与设计见 [桌面小组件](docs/desktop-widgets.md)。

0.14.0 已于 2026-10-29 发布为 [GitHub Latest](https://github.com/gjkbjj/iSicnu/releases/tag/v0.14.0)，APK 名称、大小及 SHA-256 已通过公开接口核验。此后每版同步发布安装包和 [更新日志](CHANGELOG.md)。
